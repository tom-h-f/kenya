# Kenya explorer: networks, topics, accounts, time, query

Design, 2026-10-10. Branch `feat/explorer-design`. Nothing here is built. Data facts
and every measured number are in `docs/analysis/2026-10-10-explorer-data-inventory.md`.
Machine-readable contract: `docs/plans/explorer-contract/` (`schema.json`, `types.ts`).
Builds on `docs/plans/2026-10-10-dashboard-v2.md` (producer pattern, bucket, Worker).

## Decisions already made (Tom, 2026-10-10)

- One public site, `kenya.tomfr.net`, one Worker (`kenya-ui`), many routes. No second
  hostname, no Cloudflare Access, no JWT gate, no private bucket. Account-level
  material (handles, public post text and links, community membership, who is linked
  to whom, topics by account) is allowed.
- Kept, because they are about validity and harm, not tiers: the raw bucket
  `kenya-monitor-2027` is never bound to a Worker; the producer writes only what the
  site serves; no unsupported claims; neutral language; evidence behind every link;
  no per-account hate or incitement flags; freshness stamp.

## Guardrails (each has a test, see stream E)

1. **Bucket**: Worker binds only `kenya-monitor-dashboard` (binding `DASHBOARD`,
   already so). Explorer data goes under prefix `explorer/v1/` of that bucket, written
   with the existing dashboard key. No new bucket, no new credential. The Worker serves
   whitelisted keys only, never lists the bucket.
2. **No unsupported claims**: no prevalence rate without a denominator; no raw toxicity
   series; corroboration copy stays retired; live-run counts are "surfaced under these
   parameters" with the parameters in the same view, never "N coordinated accounts".
3. **Language**: the site never calls a named account coordinated, inauthentic, bot,
   troll or similar. Use "shares retweets with", "posted near-identical text to",
   "co-active with". Every network, community and account view carries a persistent
   method caveat linking `/methodology`: co-activity is evidence accounts act together,
   not that any account is inauthentic or what its intent is. Every edge shows its
   evidence (shared posts, URLs, tag sequences, counts).
4. **No per-account flags**: no hate, incitement, toxicity, deletion, suspension or
   "account gone" field per account, ever. Aggregate by topic only, pending Tom (Q2).
5. **Denylist**: a file in the repo removes an id from all outputs on the next run.
6. **Freshness**: every view prints run id, window, computed_at and parameters from
   `stamp`, and turns amber past 36 h.
7. **Missing source** renders "not available" with a fixed reason. No placeholder.

## Proposed replacement for the policy in `2026-09-13-publishable-statistics.md`

That document's "Not publishable" list mixed a privacy rule (lifted by Tom) with
validity rules (kept). Proposed replacement, to be adopted as the new document
`docs/analysis/2026-10-10-publishing-policy.md` with the old one marked superseded by
link, not silently edited:

**Now publishable** (was withheld for privacy): handles, display names, bios and public
profile counts of accounts in a surfaced community; public post text and links used as
evidence; community membership; account-to-account links with their evidence; per-account
post counts in the window; hashtag and URL use by account and by community; which
accounts an account reposts.

**Still publishable only as before**: benchmark reproduction, relevance gate error, the
detector's own output described as such, negative results, pipeline health.

**Stays out, for validity**: any prevalence rate without a random-sample denominator (the
control arm is the only denominator and it is small: 29,213 posts); a raw toxicity or
hate series (composition drift: replies carry 3.2x the hate rate and the mix moved from
70.7% search to 72.6% replies); a count of "coordinated accounts" or communities as a
finding (it is a function of Leiden resolution, seed, and a triage budget); any
corroboration claim; any statement that a named account is inauthentic, a bot, a troll,
paid, or acting with intent; any inference about who runs an account.

**Stays out, for harm**: per-account hate, incitement, toxicity, deletion, suspension
flags (a strong accusation against a named person, from a classifier with a documented
weakness on coded speech); bios used to characterise a group; location text; any
cross-platform identity linking.

**Rules for what is shown**: state the basis on the same line as the number (snapshot,
window, parameters, standardised or not, filter); show the evidence behind any link;
timestamp everything; show denominators.

## Architecture

### Stack

- **Graph**: Sigma.js (WebGL) + graphology, pinned to what was measured: `sigma@3.0.2`,
  `graphology@0.26.0`. Measured: 7,547 nodes / 42,445 edges rendered at 120 fps (8.3 ms
  per frame over 180 camera moves), 0.14 MB gz payload; the full 10,941 / 459,744 graph
  never rendered inside 2 minutes. Cytoscape and d3-force are not chosen: in-browser
  layout of the 10,179-node backbone costs 26.8 ms per d3-force tick and 40.2 ms per FA2
  iteration, so layout is precomputed.
- **Layout**: producer, igraph, seeded. DRL took 8.6 s for 10,179 nodes / 37,422 edges,
  FR-grid 0.2 s, LGL 0.4 s; graphopt took 120 s, not used. Positions ship in the file;
  the browser does no layout.
- **App**: the existing Next 16 + OpenNext site, Tailwind as now. Charts in plain SVG
  in the style of `CollectionChart`; no new chart dependency unless a stream justifies it.
- **Query**: `@duckdb/duckdb-wasm` pinned (1.29.0 measured). Lazy-loaded on `/query`
  only. The wasm is 35.7 MB and Workers assets cap a file at 25 MiB, so serve it from
  jsDelivr at a pinned version with SRI, or from the bucket under `vendor/` (Q9).

### Sharding, loading, caching

- Layout in `explorer-contract/schema.json` (`$defs.Files`). Run files are immutable,
  `cache-control: public, max-age=31536000, immutable`; `manifest.json` is
  `max-age=60, s-maxage=300`. The app reads the manifest first and builds every URL
  from `latest_run`, so moving to a new run never needs a deploy.
- Lazy: Overview loads `overview` and `communities`; `/network` loads `graph/meta`, then
  `graph/all` after first paint; a community page loads its three files; an account card
  loads one of 64 shards (sha1(id) mod 64); search loads `search/accounts` on first
  keystroke.
- Column-oriented arrays in graphs and member lists. gzip from the platform.
- Parquet slices are range-read: the data route passes `Range` to R2.

### Producer: `kma.explorer_export`

Runs on `cloud` after the daily, same pattern as `kma-dashboard`.

- Unit `kma-explorer-export.service`, oneshot, `User=tom`, `Nice=15`,
  `IOSchedulingClass=idle`, `MemoryMax=4G` (a starting value, to be measured),
  `TimeoutStartSec=45min`, env files `v2-daily.env` (read the data bucket) and
  `dashboard.env` (write `kenya-monitor-dashboard`). Trigger: extend the daily's drop-in
  to `OnSuccess=kma-dashboard.service kma-explorer-export.service`, with
  `After=kma-v2-daily.service kma-dashboard.service` in the new unit so the two public
  producers do not overlap and neither overlaps the 12 GiB daily. No safety timer: if the
  daily fails the previous bundle stays and the manifest's stamp ages.
- Inputs (persisted, read only): `coord2/kind=daily_{runs,accounts,communities,members}`
  for the latest and previous run, **new** `daily_edges` and `daily_traces` (below), the
  window's posts for members (pinned by the window manifest, projected columns),
  `authors/` latest for members, `relevance/`, `trend_candidates/`, `control_runs/`,
  `metrics/` arm aggregates, and the dashboard's listings for the time views.
- **Change to the daily** (small, stream A): in `v2_daily.rank`, where `graph` and `nets`
  are already in memory, write `kind=daily_edges` (source, target, mask, weight_max,
  shared_retweets; about 460k rows) and `kind=daily_traces` (user_id, trace, entity for
  members of kept communities; about 270k rows) with the same `run_id`. One more `COPY`,
  no recompute. Fallback if the daily must not be touched: the exporter rebuilds with
  `coord2_run.snapshot_networks`, measured 346 s and about 2 GB. Recommended against.
- Target: under 15 minutes, under 4 GiB, niced. The dominant measured step is the
  windowed read of members' posts (287 s on a Mac). Neither is measured on `cloud`;
  stream A measures and records it in `deploy/cloud/README.md`.
- Safety: `assert_explorer_safe(bundle)` before any write: schema validation, forbidden
  field walk, verdict-word lint, denylist check, and every id present must be a member
  of a kept community or an evidence author. Write `runs/{run}/` fully, then
  `manifest.json` last; a partial bundle is never referenced. Retention: 30 runs.
- Denylist: `explorer/denylist.txt` in the repo (ids only), applied to every table before
  building, including evidence posts and slices.
- Modal budget: not used. No model loads; nothing calls X.
- Parquet slices: `accounts`, `edges` (all 459,744 fused edges as small ints plus mask,
  weight, shared), `posts` (members' window posts: id, author, created_at, kind, text,
  counts, hashtags; no flag columns), `hashtags`, `communities`. Sizes not measured;
  stream A reports them; cap 40 MB total per run.

### Worker API (one Worker, site repo)

No auth layer. The safety property is that the Worker can only read a closed set of keys.

- `GET /data/manifest.json` reads `explorer/v1/manifest.json`.
- `GET /data/{run}/{path}`: `run` must equal `manifest.latest_run` or be in
  `manifest.runs` (manifest cached per isolate 60 s). `path` must match one anchored
  regex in `lib/explorer-keys.ts`, mirroring `$defs.Files`; anything else is 404 with an
  identical body. The key is built as `explorer/v1/runs/${run}/${path}` from validated
  parts. No `list`, no cursor, no `put`, no `delete` in the code. Methods GET and HEAD.
  `Range` for `.parquet`. ETag and `If-None-Match`. Error bodies are fixed JSON.
- Existing `/api/summary` and `/api/health` stay; health also checks explorer manifest age.
- Headers: `x-content-type-options: nosniff`, CSP (self, the pinned wasm origin, and
  `worker-src blob:` only on `/query`), `referrer-policy: no-referrer`, `x-robots-tag:
  noindex` on `/accounts/*` and `/data/*` (Q8).

### Cloudflare facts (read-only probes, nothing created)

- `$CF_TOKEN` is account-owned and verifies. Its permission groups include Access Apps,
  Policies, Identity Providers and Organizations at Read and Write, Workers Scripts
  Write, Workers R2 Storage Write, Account API Tokens Write, and a separate policy with
  DNS Write. I did not probe zone Workers Routes and created nothing.
- Access holds two self-hosted apps (`ha` and an ACME-challenge bypass, both
  `ha.tomfr.net`) and one identity provider, One-time PIN. The token could in principle
  create Access apps; moot now that the site is public.
- R2 buckets: `app-name-opennext-cache`, `kenya-monitor-2027`, `kenya-monitor-dashboard`.
  Worker `kenya-ui` has exactly two bindings, `ASSETS` and `DASHBOARD`
  (`kenya-monitor-dashboard`). The raw bucket is not bound.
- This plan needs no new Cloudflare resource: no hostname, bucket, token or Access app.
  Worker deploys stay Tom's `wrangler login`.
